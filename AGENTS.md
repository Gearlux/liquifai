# Liquify Mandates

- **Zero Boilerplate:** Application startup MUST automatically initialize **LogFlow** logging and **Confluid** configuration. Users should never write bootstrap code.
- **Type-Safe DI:** Command function signatures define the dependency contract. Liquify MUST resolve dependencies from Confluid config by inspecting type annotations.
- **Bootstrap Lifecycle:** The 5-phase lifecycle (parse globals, init context, configure logging, load config, execute) MUST remain strict and sequential. Never skip or reorder phases.
- **Config Promotion:** If the first CLI argument is not a registered command, it MUST be treated as a config file path. This convention is non-negotiable.
- **Completion Fast Path Stays Stdlib-Only & Never Imports The App In-Process:** The `liquifai-complete` hot path (`_fast_complete.py` → `completion.complete_from_tree`) reads only JSON caches and imports only stdlib (+ `completion.py`). It MUST NEVER import the app or confluid (except the lazy config-override branch) IN-PROCESS, nor run a user provider in-process. Dynamic positional values (`@command(..., completions={...})` / `app.set_completions(...)`) come from providers that run ONLY at refresh time (`--refresh-completions`, the opt-in background thread, or the detached lazy-refresh helper below) and are written to `~/.cache/liquifai/<app>.values/`; the fast path just reads that cache. The ONE side effect it may have is to **detach** a self-heal subprocess for a stale/missing value cache — STATIC or DEPENDENT (see below) — a separate process, never an in-process import, never blocking. A provider may hit the network/SDK, so **background (full) refresh is OFF by default** (opt in with `LIQUIFAI_BG_REFRESH`). Providers are best-effort: a raising provider is skipped and completion falls back to the `<name>` placeholder. The value-cache key derives from the CANONICAL command path (aliases collapse to their canonical sub-app) so an alias shares the same cache.
- **Dependent Positionals: Arity + Pre-Enumeration + Lazy Self-Heal:** A provider's REQUIRED-positional-arg count (`_provider_arity`) decides its kind: **0-arg → static** (one global cache); **1-arg → dependent** (receives a dict of the EARLIER positionals, e.g. `<version>` gets `{"name": …}`). At refresh, dependent values are pre-enumerated over the cross-product of the prior positionals' STATIC cached values (capped by `max_combos`) and cached per input-hash under `<app>.values/<key>/<hash>.json`. **Both kinds self-heal lazily.** On TAB the fast path reads the cache for the exact typed inputs AND, if that cache is missing or older than `DEPENDENT_REFRESH_TTL`, calls the `lazy_refresh` callback (`make_lazy_refresh_spawner`) which DETACHES `<app> --refresh-completion-value '<json>'` (throttled by `LAZY_REFRESH_THROTTLE`; opt out `LIQUIFAI_NO_LAZY_COMPLETE`). For a STATIC positional `inputs` is `{}` and the marker/target is the flat `value_cache_path`; for a DEPENDENT one it is the typed prior-positionals dict and the per-input `dependent_value_cache_path`. That helper (`run()` → `_maybe_handle_refresh_completion_value` → `refresh_one`) runs only the one targeted provider and writes the cache, so a NEVER-refreshed static positional (e.g. a freshly-added `run list <experiment>`) populates itself on the next TAB without a manual `--refresh-completions`, and new/changed/beyond-cap dependent values self-heal the same way. `refresh_one` stamps `changed_at` in the (dependent) per-input cache ONLY when the values actually changed; `complete_from_tree` then leads the candidate list with a transient `<<positional>-updated>` hint for `DEPENDENT_NOTICE_WINDOW` seconds so the user sees the background refresh took effect (change-only, `<…>`-formatted so `_filter_prefix` drops it once a real value is typed). Prefix matching is **case-insensitive** (`_filter_prefix` lower-cases both sides) so `helios<TAB>` finds `Helios_…`. Keep this when touching `serialize_app` (tree stores `{positional: {key, kind, depends_on}}`, `CACHE_VERSION` ≥5) / `iter_completion_providers` / `refresh_value_caches` / `refresh_one` / `complete_from_tree`'s `lazy_refresh` param.
- **Completion Words & Candidates Are Space-Safe:** `$COMP_WORDS` is NEWLINE-joined by every wrapper (bash `IFS=$'\n'`, zsh `${(F)words}`, fish `string join \n`) and parsed with `completion.split_comp_words` (newline-split + unescape; falls back to whitespace for un-upgraded installs), so a token with embedded spaces (`Test Script VB`) survives as ONE word. Emitted candidates go through `completion.escape_candidate` (backslash-escape shell-specials; placeholders `<…>` left verbatim) so the shell inserts them as a single argument. Never re-introduce a raw `COMP_WORDS.split()` or unescaped candidate output — both silently break space-containing values.
- **`--docs` Is `--help` In Line Layout:** `--docs` renders the SAME code-extracted option docs as `--help` (one `confluid.get_hierarchy` source of truth) via `report.show_configuration(..., layout="lines")` — one option per line, greppable. Keep the two layouts data-identical; never let `--docs` extract differently from `--help`/completion.
## Project Quality Gates
To run the full quality suite for Liquify, execute the following commands from the project root:

```bash
# From ~/source
isort --settings-file liquifai/pyproject.toml liquifai
black --config liquifai/pyproject.toml liquifai
flake8 --config liquifai/.flake8 liquifai
mypy --config-file mypy.ini liquifai
pytest --cov=liquifai --cov-report=term-missing liquifai/tests
```

**Note:** Always use the root `mypy.ini` for cross-project type checking, as it contains the correct `mypy_path` for all internal packages.
